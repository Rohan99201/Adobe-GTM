Deploying this for real

Two ways to ship the bridge script — pick one, don't run both:

A. In the page's own <head>, before the GTM snippet (used on this page). Zero extra requests, runs the instant the first push happens, and safely replays any events that fired before it loaded. This is the reliable choice when page-load timing matters.

B. As a GTM Custom HTML tag on an Initialization – All Pages trigger, if you'd rather manage it from GTM without a code deploy. Use the identical script body. Caveat: any adobeDataLayer event that fires before GTM itself finishes loading won't be caught, since the tag can't run until the container does — acceptable for most sites, but worth checking against your slowest-loading pages.

Page-load considerations already baked in

• adobeDataLayer init + bridge are inline and tiny (no blocking network request).
• The GTM snippet is Google's stock async loader — it never blocks rendering.
• The bridge only runs its (cheap) transform logic on actual pushes, not on a timer or poll.
• No layout, images, or web fonts to fetch — this demo has effectively zero render cost beyond your GTM container's own tags.
